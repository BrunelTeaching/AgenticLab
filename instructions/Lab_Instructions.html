Agentic SE Lab — Dissect an Agent

Module: CS3616 Software Engineering · Agentic Software Engineering, Lecture 1

You will need: VS Code, Python 3.10+, git, and the class API key (provided in Setup below).

Lab form: record your Warm-up, Part A and Part C answers in the lab form.

Time: ~30–40 minutes  ·  Format: individual or pairs

What this agent is, in one line: an events finder — you tell it your interests and your city, it searches the web for upcoming tech events, hackathons and meetups, and gives you a short list with dates, venues and sign-up links.

The big idea: the lecture said an agent is a language model that uses tools in a loop to reach a goal. People talk about "agents" as if they were magic. They are not. In this lab you take a real one apart: about 40 lines of Python — a loop, some tools, a memory file — wrapped around one call to a model. You run it, watch it decide to search the web for evidence, then change what it does by editing its memory and giving it a new tool.

The model is real (a free gpt-oss model running on Groq), so you see it genuinely choose when to reach for a tool. Everything around the model is plain code you can read in agent/. Take the model away and the "agent" can't think — that is the whole point.

A Run it, and watch the model decide Compulsory

Ask it something it can answer from general knowledge:

python run.py "What is a hackathon?"

It answers straight away — no tool call, one trip to the model. Now ask it to actually find some, which it can't know from training alone:

python run.py "AI hackathons for students in London this term"

This time the loop has more steps — the model chooses to search:

QUESTION  AI hackathons for students in London this term
STEP 1  THINK   I need to look up current events.
STEP 1  ACT     web_search({'query': 'student AI hackathons London 2026'})
STEP 1  OBSERVE Results for 'student AI hackathons London 2026':
STEP 2  THINK   Here are three upcoming ones ...
ANSWER  1. HackLondon — Sat 6 Dec, Brunel University — https://...
        2. ...

Same code, same model — the only difference is that the model decided it needed current information and reached for a tool. That decision, made by the model and carried out by the harness, is what makes this an agent and not a chatbot. Try a few of your own — your real interests, your real city.

Open the agent and find the model

Read agent/harness.py — the whole loop is about a dozen lines: call the model, if it asked for a tool run it and feed the result back, otherwise return the answer. Then open agent/model.py: one function calls the model. That is the entire "intelligence". Everything else is ordinary code.

Same shape as Claude Code and opencode

Real terminal agents run this exact loop with a real LLM in the model.py slot and richer tools (read, edit, bash). Give a goal → model asks for a tool → harness runs it → result goes back → repeat until done. You've just built the smallest honest version of one.

Model — model.py: the one model call the agent wraps
Memory — AGENTS.md in the system prompt (the persona, the list format, "don't invent events")
Tools — web_search; its result is fed back into the loop
Loop — harness.py: Think → Act → Observe until the model is done

B Change the agent by editing its MEMORY Compulsory

Open workspace/AGENTS.md. This file is loaded into the model's system prompt on every call, so it steers the agent — with no code change. Make a few edits and re-run to feel it:

  • Change up to 3 events to up to 5 events, and add - For each event, add a one-line "why you'd go".
  • Add a rule: - Only list events that are free to attend. — the shortlist changes.
  • Add a rule: - Always answer in French. — and watch the whole agent switch language.
python run.py "game-dev meetups near Uxbridge"

Nothing in the Python changed — you reprogrammed the agent's behaviour through a text file. This is the single most important skill in agentic engineering: you steer an agent by curating its context.

No API key handy?

You can still prove the memory reaches the model. Run:

python -c "from pathlib import Path; from agent.memory import load_system_prompt; print(load_system_prompt(Path('workspace')))"

Your edited rules appear in the system prompt the model receives on every call.

Why this matters

Real tools work the same way: Claude Code reads CLAUDE.md, many agents read the AGENTS.md convention. Build commands, conventions, tone and no-go zones live in memory, not in prompts you retype. A good AGENTS.md is portable — it moves with you when you switch tools.

C Give the agent a new TOOL Compulsory

Event-hunting involves a bit of maths — "how many days until it?", "is the ticket under £20?" — and language models are notoriously shaky at arithmetic. Give the agent a calculator so it can work numbers out properly instead of guessing. Try a sum first:

python run.py "How many days are there in 7 weeks?"

It may slip up, or awkwardly search the web. Give it a proper tool instead.

1. Write the tool function

Open agent/tools.py. Next to _web_search, add a calculator (safe — it parses the expression rather than running eval):

import ast, operator
_OPS = {ast.Add: operator.add, ast.Sub: operator.sub, ast.Mult: operator.mul,
        ast.Div: operator.truediv, ast.Pow: operator.pow, ast.USub: operator.neg}
def _calc(node):
    if isinstance(node, ast.Constant): return node.value
    if isinstance(node, ast.BinOp):   return _OPS[type(node.op)](_calc(node.left), _calc(node.right))
    if isinstance(node, ast.UnaryOp): return _OPS[type(node.op)](_calc(node.operand))
    raise ValueError("unsupported")
def _calculator(args):
    try:    return f"{args['expression']} = {_calc(ast.parse(args['expression'], mode='eval').body)}"
    except Exception as e: return f"calculator error: {e}"

2. Register it — a name, a description, an input schema

Add a Tool(...) to the BUILTIN_TOOLS list. The description is what the model reads to decide when to reach for it:

Tool(
    name="calculator",
    description="Evaluate an arithmetic expression, e.g. '7 * 7'. Use this for "
                "any maths rather than working it out yourself.",
    input_schema={"type": "object",
                  "properties": {"expression": {"type": "string"}},
                  "required": ["expression"]},
    run=_calculator,
),

3. Watch the model choose between tools

python run.py "How many days are there in 7 weeks?"   # now ACT calculator(...) -> 49
python run.py "AI hackathons in London this term"     # still ACT web_search(...)

You gave the agent a new ability by registering a tool — the loop in harness.py never changed. And notice the model now picks the right tool per request: numbers → calculator, events → search. That routing is the model's job; your job was to offer the tool.

4. Prove it with the tests

Open tests/test_part_c.py, delete the pytest.skip(...) line near the top, then:
